Enote 项目分析报告

1. 项目概述

Enote 是一款跨平台乐谱管理应用。前端基于 Flutter，负责本地 SQLite 数据管理、乐谱导入与编辑、用户登录与设置；后端采用 Flask + MongoDB(GridFS) 提供用户认证、乐谱云同步和 OMR（图像转 MXL）能力。Audiveris 与 OpenCV 作为识谱工具链。

  • 客户端：Flutter + Provider + sqflite + SharedPreferences + WebView (Flat Embed)。
  • 服务端：Flask + PyMongo + JWT + bcrypt + OpenCV + Audiveris CLI。
  • 核心能力：乐谱导入/编辑/分类、用户认证、云同步、图像识谱。

2. 目录结构总览

  • client/：Flutter 工程，含 lib/ 源码、assets/web 的 Flat 编辑器集成、平台目录（android/ios/windows）。
  • server/：Flask 服务，app/routes 提供 API，src/audiveris 打包第三方识谱工具与模型。
  • images/：README 中引用的 UI 示意图。
  • README.md：总体说明与环境配置指南。
  • requirements.txt：服务端依赖清单。

3. 客户端（Flutter）

3.1 架构摘要

  • 状态管理：client/lib/main.dart 通过 ChangeNotifierProvider 注入 ThemeProvider 管理浅色/深色模式。
  • 数据持久化：sqflite + path_provider 保存 Score、CollectionInfo、CollectionItem 三类表（client/lib/models/database_helper.dart）。
  • 网络通信：各页面直接使用 package:http/http.dart 访问 Flask API，地址默认指向模拟器网关 10.0.2.2。
  • 文件导入：client/lib/widgets/import_score.dart 负责从本地选取 MXL/图片、调用 OMR 服务、解压 MXL 并写入本地。
  • 乐谱编辑：client/lib/pages/score_detail_page.dart 使用 WebViewController 与 assets/web/editor.html 里的 Flat Embed 通过 JS channel 传输 MusicXML。

5. 数据通信方式

调用方HTTP接口载荷/要点说明
Flutter POST /login JSON：用户名、密码、sync_enabled 返回 JWT；保存在 SharedPreferences。
Flutter POST /register JSON：用户名、密码（sync 标志未上传） 返回提示文本及新用户 ID。
Flutter POST /reset_password JSON：用户名、新密码 无 token，公开接口。
Flutter GET /logout Header：Authorization（裸 token，未加 Bearer） 更新 Mongo 中 last_logout。
Flutter POST /sync_enabled JSON：sync_enabled，Header：token 更新 Mongo 用户字段。
Flutter POST /edit_user_info JSON：新昵称/新密码，Header：token 修改用户信息。
Flutter POST (multipart) /scores/sync 字段 scores（JSON 字符串）+ 多个 MXL 文件 服务器当前用 request.json 读取，存在兼容问题（§8）。
Flutter POST /scores/delete JSON：scoreId 未校验 token。
Flutter POST (multipart) /omr 上传图片文件 返回 MXL 二进制流。
Flutter ↔ Flat WebView JS Channel FlutterPostMessage/receiveXmlFromFlutter 传输 MusicXML 字符串 WebView 与 Flutter 本地通信。

6. 数据处理方法

6.1 客户端

  • SQLite 持久化：通过 DatabaseHelper 初始化数据库，DAO 层读写 Score/CollectionInfo/CollectionItem。
  • 乐谱文件：使用 archive.ZipDecoder 解压 MXL，抽取 XML 以供 WebView；保存时用 ZipEncoder 重新生成 MXL。
  • 同步数据准备：syncScoresWithServer() 将 DB 记录映射成 JSON + 文件，打包为 multipart 请求。
  • 用户状态：SharedPreferences 保存 token / username；UserSession 充当本地占位用户。
  • UI 逻辑：多处使用 showDialog/Navigator 管理弹窗与路由；Provider 仅负责主题。

6.2 服务端

  • 密码处理：注册/修改密码时使用 bcrypt 哈希；登录使用 bcrypt.checkpw 校验。
  • 令牌生成：utils/auth.py 通过 PyJWT 生成 HS256 token（无过期时间）。
  • 乐谱存储：元数据保存在 Mongo 集合 scores，MXL 文件存入 GridFS，字段 fileId 引用。
  • 同步比较：根据客户端提交的 modifyTime 与服务器版本比对决定覆盖方向。
  • 图像处理：OpenCV 将图片放大、转灰度再写回磁盘，设置 TESSDATA_PREFIX 后调用 Audiveris 生成 MXL。

7. 关键业务流程

  1. 应用启动：加载主题 Provider → 进入 ScoreHomePage，初始化 ImportHandler 并从 SQLite 读取曲谱/谱集。
  2. 用户登录：在 LoginPage 输入账号 → 调用 /login → 成功后缓存 token、跳转 UserInfoPage。
  3. 曲谱导入：点击导入 → 选择 MXL 或图像 → 若图像则调用 /omr 返回 MXL → 保存到本地临时文件 → 回调插入 SQLite → 跳转编辑页。
  4. 曲谱编辑：编辑页加载本地 MXL → 注入 XML → 用户编辑 → 触发保存 → WebView 回传 XML → 重打包写回文件并更新数据库时间戳。
  5. 云同步：下拉刷新或初始化时调用 syncScoresWithServer() → 打包本地数据请求服务端 → 按修改时间合并 → 服务器可能返回更新后的文件数据。
  6. 谱集管理：通过对话框创建/重命名谱集 → 使用 DAO 在 CollectionItem 中维护顺序 → 详情页 (CollectionDetailPage) 展示谱集内曲谱。
  7. 用户设置：UserInfoPage 控制云同步开关、编辑资料、退出登录；MoreSettingsPage 切换主题、进入隐私政策/关于我们。

8. 风险与改进建议

  1. 谱集 DAO 与数据库结构不匹配：client/lib/models/collection_dao.dart:16 仍对 Collection 表插入/查询，而 client/lib/models/database_helper.dart:52 仅构建 CollectionInfo 与 CollectionItem。调用这些方法会抛出 “no such table: Collection”。建议移除旧 DAO 或改为操作新表。
  2. 同步请求字段不一致：client/lib/pages/score_home_page.dart:232 发送的 JSON 使用 Access_time 字段，而数据库列为 Modify_time；同一方法未携带 token。服务端 server/app/routes/scores.py:16 使用 request.json 读取元数据，但 multipart 请求不会填充 request.json，导致 metadata 始终为空。应统一字段名并使用 request.form 或 request.files + json.loads 解析。
  3. 乐谱接口缺乏鉴权：server/app/routes/scores.py:10（同步）与 server/app/routes/scores.py:110（删除）未校验 JWT，使得任何人都能操作云端数据。应像用户接口一样验证 token 并按用户名隔离数据。
  4. 返回值含不可序列化对象：server/app/routes/scores.py:78 在同步响应中直接返回 Mongo 文档（包含 ObjectId），默认 jsonify 无法序列化，会触发 500。需主动将 _id/fileId 转为字符串。
  5. 本地用户标识固定：client/lib/models/user_session.dart:2 始终返回 dev_mock_user，无论是否登录。云同步及本地 DB 实际无法区分真实用户。建议登录成功后写入真实用户 ID/用户名，并在退出时清理。
  6. 缺少同步结果回流：client/lib/pages/score_home_page.dart:255 仅打印服务端消息，没有处理“服务端较新”场景返回的 Base64 文件，用户端无法自动覆盖。需解析响应并更新 SQLite 与本地文件。
  7. 安全与稳定性：密码相关接口（如 /reset_password）缺少频率控制；omr 接口未限制文件类型及大小；Audiveris 调用依赖本地路径，部署环境需谨慎配置。
